# S21 Slot Bot

Telegram-бот для автоматического поиска свободных слотов на P2P-проверки в **Школе 21**.

Бот работает от имени вашего аккаунта Школы 21: находит проекты, которым нужны P2P-проверки, следит за доступными
слотами и может либо сообщить о найденном времени, либо автоматически записаться. Кроме того, бот отслеживает проверки,
на которые записались вы, и проверки, на которые другие студенты записались к вам.

> [!IMPORTANT]
> Это неофициальный клиент Школы 21. Для работы ему нужны ваши учетные данные Школы 21 и отдельный Telegram-бот.
> Запускайте приложение только в окружении, которому доверяете.
> Для подключения к Telegram и работы приложения необходим VPN.

## Возможности

- поиск проектов, которые сейчас находятся на этапе P2P-проверок;
- несколько одновременных поисков по разным проектам;
- два режима работы:
    - **🔎 Искать слоты** — найти свободный слот и сообщить о нем;
    - **✅ Записаться** — автоматически записаться на первый подходящий слот;
- выбор количества необходимых проверок;
- настройка окна поиска;
- ручной ввод времени;
- настройка интервала опроса;
- просмотр текущих записей, найденных слотов и статистики;
- отслеживание проверок, на которые вы записались для проверки своих проектов;
- отслеживание проверок, на которые другие студенты записались к вам;
- уведомления о новых записях к вам на проверку;
- уведомления об отмененных и приближающихся проверках в обеих ролях;
- остановка, перезапуск, изменение и удаление поисков;
- автоматическое обновление списка актуальных проверок;
- повторные HTTP-запросы при временных сетевых и серверных ошибках.

Все управление происходит через личный чат с вашим Telegram-ботом.

## Как это работает

После запуска приложение авторизуется в Школе 21 от вашего имени и работает с проектами и P2P-слотами, доступными вашему
аккаунту.

При создании поиска вы выбираете:

1. проект;
2. режим — только найти слот или найти и записаться;
3. необходимое количество проверок;
4. начало и конец окна поиска;
5. при необходимости — собственный интервал опроса.

После подтверждения создается отдельный поисковый бот. Он с заданным интервалом проверяет свободные слоты до тех пор,
пока не выполнится одно из условий:

- найден подходящий слот;
- выполнено необходимое количество записей;
- истекло окно поиска;
- поиск остановлен вручную;
- произошла ошибка, после которой продолжение работы невозможно.

В режиме **🔎 Искать слоты** поиск останавливается после первого найденного слота, а в Telegram появляется возможность
записаться вручную.

В режиме **✅ Записаться** приложение само пытается занять первый подходящий слот.

После команды `/start` доступны основные разделы:

| Раздел         | Назначение                                                            |

Для работы бота нужны:

- аккаунт Школы 21;

компьютер.

Для запуска приложения напрямую без Docker дополнительно нужны:

- **Python 3.14+**;
- **uv**.

## Настройка Telegram

### 1. Создайте бота

Откройте [@BotFather](https://telegram.me/BotFather) в Telegram, выполните `/newbot` и следуйте инструкциям.

В результате вы получите токен вида:

```text
123456789:AA...
```

Он понадобится как `TG_BOT_TOKEN`.

Не публикуйте этот токен и не добавляйте его в Git.

### 2. Узнайте свой Telegram user ID

Далее необходимо узнать числовой ID вашего Telegram-пользователя. Приложение проверяет пользователя и приватный чат,
поэтому управлять вашим экземпляром бота сможет только указанный
аккаунт.

Чтобы узнать свой ID через API, напишите сообщение из своего аккаунта в ваш бот от **@BotFather** и запросите информацию
о полученных сообщениях через `https://api.telegram.org/bot<YOUR_BOT_TOKEN>/getUpdates`, придет ответ следующего
формата:

<details>

```json
{
  "ok": true,
  "result": [

        "from": {},

          "type": "private"
        },
        "date": 1234567890,
        "text": "hello!"
      }
    }
  ]

```

Укажите полученный `result.message.chat.id` в переменной `TG_CHAT_ID`.

</details>

Альтернативный способ - отправить сообщение в одного из ботов, который возвращает информацию о пользователе -
например, [@getmyid_bot](https://t.me/Getmyid_bot). Из ответа необходимо скопировать `Your ID` в переменную

## Конфигурация

Создайте в корне проекта файл `.env`:

```dotenv
S21_USERNAME=your_school21_login
S21_PASSWORD=your_school21_password
S21_CAMPUS=Moscow

TG_BOT_TOKEN=your_telegram_bot_token
TG_CHAT_ID=123456789

TIMEZONE=Europe/Moscow
```

`.env` должен быть исключен из Git.

### Обязательные параметры

| Переменная     | Назначение           |
|----------------|----------------------|
| `S21_USERNAME` | Логин Школы 21       |
| `S21_PASSWORD` | Пароль Школы 21      |
| `S21_CAMPUS`   | Кампус Школы 21      |
| `TG_BOT_TOKEN` | Токен Telegram-бота  |
| `TG_CHAT_ID`   | Ваш Telegram user ID |

Параметр `S21_CAMPUS` определяет, какое значение будет у параметра `x-edu-org-unit-id` в заголовках запроса.

Доступные на текущий момент кампусы (чтобы добавить свой кампус, создайте feature request):

* `Moscow`
* `Ufa`

### Дополнительные параметры

У всех параметров ниже есть значения по умолчанию.

| Переменная                      |    По умолчанию | Назначение                                               |
|---------------------------------|----------------:|----------------------------------------------------------|
| `TIMEZONE`                      | `Europe/Moscow` | Часовой пояс для ввода и отображения времени             |
| `MAX_BOTS`                      |             `5` | Максимальное количество созданных поисков                |
| `POLL_INTERVAL_SEC`             |            `30` | Интервал проверки свободных слотов, секунд               |
| `REFRESH_BOOKINGS_INTERVAL_SEC` |            `60` | Интервал обновления текущих проверок, секунд             |
| `S21_CACHE_TTL_SEC`             |           `300` | Время жизни кэша данных Школы 21, секунд                 |
| `S21_TIMEOUT_TOTAL_SEC`         |            `90` | Общий HTTP-таймаут, секунд                               |
| `S21_TIMEOUT_CONNECT_SEC`       |            `10` | Таймаут подключения, секунд                              |
| `S21_TIMEOUT_READ_SEC`          |            `20` | Таймаут чтения ответа, секунд                            |
| `S21_MAX_REQUEST_RETRIES`       |             `7` | Максимальное число попыток HTTP-запроса                  |
| `S21_RETRY_DELAY_SEC`           |             `2` | Начальная задержка между повторными попытками, секунд    |
| `S21_RETRY_BACKOFF`             |             `2` | Множитель задержки между повторными попытками            |
| `LOG_LEVEL`                     |          `INFO` | Уровень логирования                                      |
| `LOG_SILENCE_LIBRARIES`         |               — | Библиотеки, для которых нужно оставить только `WARNING+` |

Обычно менять дополнительные параметры не требуется.

## Использование

### Создание поиска

Нажмите `▶️ Начать`.

Бот загрузит проекты, для которых сейчас доступны P2P-проверки. Если проект один, он будет выбран автоматически.

Далее выберите режим.

### 🔎 Искать слоты

Бот ищет подходящее время, но **не записывает вас автоматически**.

Когда слот найден:

- поиск останавливается;
- приходит уведомление со временем;
- появляется возможность записаться вручную.

Это подходит, если вы хотите самостоятельно подтвердить запись.

### ✅ Записаться

Бот автоматически пытается записаться на первый найденный подходящий слот.

Перед запуском можно выбрать, сколько проверок необходимо. Бот учитывает уже существующие записи по проекту.

- Если слот успел стать недоступным, поиск продолжит работу.
- Если набрано необходимое количество проверок, то и в этом случае поиск не останавливается. Это сделано для того, чтобы
  вплоть до конца выбранного окна поиска у вас сохранялось необходимое количество проверок - если их будут отменять, бот
  будет перезаписываться.
- Если для записи не хватает PRP, бот сообщит об этом и остановит поиск.

### Окно поиска

Для начала доступны быстрые варианты:

- сейчас;
- +30 минут;
- +1 час.

Для конца окна доступны интервалы относительно начала:

- +1 час;
- +2 часа;
- +4 часа;
- +8 часов;
- +12 часов.

Время можно вводить вручную
в [поддерживаемых форматах](https://pydantic.dev/docs/validation/2.0/usage/types/datetime/#validation-of-datetime-types),
например:

```text
12:30 (сегодняшнего дня)
2026-08-23 12:30
2026-08-23 12:30:45
+01:15 (через 1 час 15 минут)
P1D (через день)
```

Ввод и отображение времени происходят в часовом поясе `TIMEZONE`.

### Несколько поисков

Можно создать несколько независимых поисков. По умолчанию разрешено до `5`; лимит задается через `MAX_BOTS`.

У каждого поиска есть собственные:

- проект;
- режим;
- необходимое количество проверок;
- окно поиска;
- интервал;
- статистика;
- состояние.

### Изменение поиска

Через `✏️ Изменить` можно изменить:

- начальное время;
- конечное время;
- режим;
- количество проверок;
- интервал опроса.

Там же можно перезапустить остановленный поиск.

При изменении интервала активный поиск перезапускается с новым значением.

### Остановка и удаление

`⛔ Остановить` прекращает выполнение поиска, но сохраняет его конфигурацию. Его можно позднее перезапустить через
`✏️ Изменить`.

`🗑️ Удалить` полностью удаляет поиск из текущего экземпляра приложения.

Поиск также автоматически удаляется, когда заканчивается его временное окно.

### Статус

Раздел `📌 Статус` показывает:

- количество активных и созданных поисков;
- состояние фонового обновления проверок;
- текущие проверки в обеих ролях и найденные слоты;
- состояние каждого поиска;
- количество необходимых и уже назначенных проверок;
- режим поиска;
- окно поиска;
- последнюю попытку;
- число успешных и неуспешных попыток;
- нестандартный интервал опроса, если он был изменен.

## Уведомления о проверках

Приложение отдельно от поиска слотов отслеживает актуальные P2P-проверки в Школе 21 в обеих ролях:

- **вас проверяют** — проверки, на которые вы записались для проверки своего проекта;
- **вы проверяете** — проверки, на которые другой студент записался к вам.

Бот может сообщить:

- об успешно созданной записи;
- о найденном слоте в ручном режиме;
- о слоте, который успел стать недоступным;
- о недостатке PRP;
- о новой записи другого студента к вам на проверку;
- об отмене ранее известной проверки;
- о приближающейся проверке независимо от вашей роли.

Если одновременно появилось несколько новых записей к вам на проверку или было отменено несколько проверок, они
объединяются в одно уведомление.

В уведомлении о проверке отображаются доступные на этот момент данные: время, название проекта, логин второго участника
и ссылка для подключения.
Школа 21 предоставляет информацию о проекте или студенте за 15 минут до начала проверки — до этого времени бот покажет
только доступные данные. Напоминание о предстоящей проверке так же отправляется примерно за **15 минут**.

При запуске приложение загружает уже существующие проверки, на которые другие студенты записались к вам, без отправки
лишних уведомлений о новой записи. После этого бот уведомляет только о новых изменениях.
Фоновое обновление информации о проверках можно останавливать и запускать вручную в разделе `📌 Статус`.

## Авторизация и безопасность

Для работы приложению необходимы `S21_USERNAME` и `S21_PASSWORD`.

Авторизация выполняется автоматически через систему авторизации Школы 21. После входа приложение получает access- и
refresh-токены и использует их для последующих запросов к платформе.

Важно:

- пароль используется только для авторизации;
- пароль хранится как секретное значение конфигурации приложения;
- access- и refresh-токены хранятся только в памяти процесса;
- при истечении access-токена приложение пытается обновить его автоматически;
- при `401` или `403` выполняется повторная авторизация;
- кэш данных также находится только в памяти;
- Telegram-бот принимает команды только от пользователя, чей ID указан в `TG_CHAT_ID`;
- токен Telegram-бота маскируется в HTTP-логах.

Сам файл `.env` содержит реальные секреты в открытом виде. Поэтому:

- не коммитьте `.env`;
- не отправляйте его другим людям;
- на VPS установите права `chmod 600 .env`;
- не запускайте чужие сборки проекта со своими учетными данными;
- при компрометации `TG_BOT_TOKEN` перевыпустите его через BotFather.

## Хранение состояния

Приложение не использует постоянную базу данных для поисков.

Состояние поисков, статистика, кэш и временные данные хранятся **в памяти**.

После перезапуска приложения или контейнера созданные поиски не восстанавливаются автоматически — их нужно создать
заново через Telegram.

Фактические записи на P2P-проверки хранятся на стороне Школы 21 и при перезапуске приложения не исчезают. После запуска
бот заново получает актуальные проверки с платформы, в том числе проверки, на которые другие студенты записались к вам.

## Если что-то пошло не так

Если вы обнаружили баг - заведите его в Issues, приложите логи (если проблема воспроизводимая - то с `LOG_LEVEL`=
`DEBUG`).

### Бот не отвечает на `/start`

Проверьте:

1. приложение запущено;
2. `TG_BOT_TOKEN` указан правильно;
3. `TG_CHAT_ID` совпадает с вашим Telegram user ID;
4. запущен только один экземпляр приложения с этим Telegram-токеном.

Если одновременно запустить два экземпляра одного Telegram-бота через polling, Telegram будет завершать запросы одного
из них с ошибкой `Conflict`.

### Не удается войти в Школу 21

Проверьте `S21_USERNAME` и `S21_PASSWORD`.

Если учетные данные верны, проблема может быть временной на стороне платформы или страницы авторизации. Посмотрите логи
приложения.

### Ошибка "У вас нет прав на выполнение данной операции"

Вероятно, ваш кампус указан неверно, проверьте `S21_CAMPUS`.

### Поиск завершился с ошибкой

Временные сетевые ошибки, некорректные gateway-ответы и серверные ошибки повторяются автоматически с увеличивающейся
задержкой.

Если все попытки исчерпаны, соответствующая задача останавливается. Ее можно позднее перезапустить через
`✏️ Изменить`.

### Docker-контейнер не работает

```bash
docker compose ps
docker compose logs --tail=200 school21-bot
```

Для полной пересборки:

```bash
docker compose down
docker compose build --no-cache
docker compose up -d
```

uv sync --locked

docker compose up -d --build

Telegram → ваш бот → /start → ▶️ Начать
